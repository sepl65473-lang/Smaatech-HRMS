This is the Smaatech HRMS Android app: an Expo / React Native client for the existing HRMS API in `../server`. Read `README.md` first.

## Expo has changed — do not trust your training data

Expo ships breaking changes every SDK release. Before writing code that touches an Expo, EAS, or React Native API:

1. Read the major version of the `expo` package in `package.json`.
2. Check the matching versioned docs: `https://docs.expo.dev/versions/v<major>.0.0/`, or the type definitions in `node_modules`.

## Commands

```bash
npx expo install <package>  # always use instead of npm install for Expo/RN packages
npm run typecheck
npm run lint
npm run doctor
```

Run lint and typecheck before declaring any task done.

## Project rules

- The server is the authority. Every rule (roles, face match, liveness, geofence, shift timing, leave balance) lives in `../server`. The app collects input and shows the server's answer; never re-implement a decision here, and never show success before the server confirms it.
- Do not invent endpoints. Every call in `src/services/endpoints.ts` maps to a route in `../server/src/routes`.
- Navigation is React Navigation (native stack + bottom tabs) in `src/navigation`. The tab set is chosen from the role in `src/auth/permissions.ts`.
- `/attendance` requests are rate limited to 40 per user per 15 minutes, reads included. Keep them few and cached.
- No secrets in this folder. `app.config.ts` and everything in `src` ship inside the APK.
- `android/` is generated by `expo prebuild`. Do not create or edit it by hand; configure native behaviour in `app.config.ts`.
- Native modules mean Expo Go cannot run this app. Use a development build (`eas build --profile development`).
